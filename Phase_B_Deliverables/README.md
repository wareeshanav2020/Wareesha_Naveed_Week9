# Olist E-Commerce Business Intelligence — Phase B

## Project Overview

I developed this project to explore e-commerce data and present analytical findings through a business intelligence dashboard. In Phase B, I reused the processed data, customer segmentation, sales forecasting outputs, and trained model from Phase A to prepare a Streamlit application for analysis and decision support.

## Objectives

- Present business indicators in a single dashboard.
- Explore customer segments and their profiles.
- Visualize historical sales and forecast results.
- Provide model predictions where the trained model and required inputs are available.
- Present feature-importance information and model risks.
- Test the application and document the results.

## Technologies Used

## Installation

I install the required libraries using:

```bash
pip install -r requirements.txt
```

## Running the Application

I open a terminal in the project folder and run:

```bash
streamlit run app.py
```

Streamlit normally opens the application in a browser at:

```text
http://localhost:8501
```

## Dashboard Features

1. Executive Overview
2. Customer Segmentation
3. Sales Trends
4. Forecasting
5. Prediction
6. Model Explanation
7. Business Recommendations

The available charts and predictions depend on the supplied data files, column names, and saved model.

## Data and Model Requirements

I use the processed analytical CSV for business indicators, a customer dataset containing cluster labels for segmentation, appropriate historical or forecast sales data for sales visualizations, a feature-importance CSV for model explanation, and the actual trained model for predictions.

The prediction form must use the exact input features and preprocessing expected by the saved model. A CSV containing test predictions is not a substitute for the saved model file.

## Application Testing

I record the results in `application_test_cases.csv`. I test application launch, data loading, dashboard sections, model loading, predictions, and error handling. I update each test's status based on the actual observed result.

## Limitations

The application depends on compatible input files and a correctly saved model. Forecasts and model predictions may contain errors. Results are intended to support analysis and decision-making, not to guarantee outcomes.

## Conclusion

This project brings data analysis, customer segmentation, forecasting, and predictive modelling outputs into a single dashboard. Phase B extends Phase A by presenting the results in a form that is easier to inspect and use for business decision support.
